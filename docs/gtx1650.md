# GTX 1650 (TU117, no tensor cores)

A GTX 1650 is compute capability 7.5 but has no tensor cores. The sm_75 kernels run (see
[sm75.md](sm75.md)), but the 4-step SFT DiT needs its distilled LoRA. On a card without tensor cores,
runtime LoRAs were previously force-merged into the INT8 ConvRot block weights; requantizing 252
adapters this way visibly destroys the image (a regular dot lattice, banded background and wrong
detail) even though the INT8 GEMMs are bit-exact and the VAE round trip is clean.

## Runtime LoRA side branch (this branch)

Instead of merging, sm_75 now runs the LoRA as a side branch without tensor cores:

- `SideBranches` uploads both A and B factors as fp32; `t` stays fp32. No fp16 intermediate is used by LoRA.
- `compute_t` converts its bf16 input to fp32 (exact) and uses cuBLASLt's fp32 GEMM; the small-K delta GEMM also
  uses fp32, which is 2.8-4.5x faster than cuBLASLt's fp16 path on this GPU. The fp32 delta output is rounded once
  to bf16 before the SIMT add-back.
- The base INT8 ConvRot GEMM uses a native `__dp4a` tiled kernel instead of Turing's emulated `m8n8k16` MMA
  (bit-exact int32 accumulation and dequantisation order; ~1.3x faster). The gated-residual and SiTU epilogues
  are the same DP4A GEMM followed by the bit-exact SIMT elementwise kernels, both on the runtime-LoRA side branch
  and on the plain (no-LoRA) path.
- Exact attention on GTX 16xx uses `kernels/sm75/attention_f32_sm75.cu`: the two matmuls are cuBLASLt fp32 GEMMs
  (0.7–1.5 TFLOPS instead of the emulated fp16 MMA's 0.3) and the softmax is SIMT; scores are processed one head at a
  time and kept in an enlarged attention workspace. It needs ~40 MiB at 256² and passes the same `sm75_check`
  cosine/LSE gates.
- The low-rank Δ is added to the base GEMM's bf16 output in fp32 by a SIMT epilogue
  (`kernels/sm75/lora_sm75.cu`), then the site's own `gated_residual`/`situ_glu` epilogue runs
  (`models/moss_dit/dit_block_quant.cpp`).
- `force_lora_merge_on_sm7x()` no longer overrides the requested placement, so `--lora-placement
  side_branch` (and the default) work on Turing.

No offline conversion is needed: use the original INT8 DiT and the runtime LoRA:

```sh
moss-infer generate --model <bundle> --dit moss_image_sft_int8_convrot.safetensors \
  --tier high --lora moss_image_sft_4step_v2.0.safetensors --lora-scale 1.0 \
  --lora-placement side_branch --attention exact \
  --prompt "best quality, highres, a red apple on a wooden table soft light" \
  --steps 4 --cfg 1 --shift 5 --seed 42 -o out.png
```

Verified on a GTX 1650 4 GiB at 256²: image matches the official reference (stem, water droplets,
clean background), ~2.5 s/step from the page cache and ~2.1 s/step from pinned host weights. See [sm75.md](sm75.md).

## 8-bit attention

Like every other architecture, an unset `--attention` on GTX 16xx now resolves to the tier's 8-bit default
(`q8_fp16`; `q8_fp8` has no e4m3 MMA on Turing). Its QK dot product uses native `__dp4a` instead of Turing's
emulated INT8 MMA (1.3-1.4x faster, bit-identical output to the MMA path); `MI_Q8_DP4A=0` selects the MMA path.
`--attention exact` remains available. `q8` is lossy, but so is the INT8 ConvRot DiT that the `high` tier already
runs. Its P·V matmul still uses the emulated fp16 MMA.

## Other measured speedups

- `--mode max_speed` keeps more DiT blocks resident with pinned host weights: 2.07 vs 2.51 s/step at 256²
  (4 steps, same seed/prompt, bit-identical PNG), at the cost of a longer one-time load and more host RAM.
- All INT8 ConvRot epilogues now use native DP4A: the fused `gated_residual` / `situ_glu` CUTLASS kernels were
  replaced by a DP4A plain GEMM plus the existing bit-exact SIMT epilogue (1.4-1.55x on the GEMM itself,
  2.30 -> 1.87 s/step for a no-LoRA 256² run, bit-identical latent). The runtime-LoRA side branch already did this.
